THE BIG PICTURE
FastAPI listens. PostgreSQL remembers. You make it lovely.

The browser calls the FastAPI endpoints. FastAPI validates requests, checks identity and permissions, and reads or updates data in PostgreSQL through SQLAlchemy.

01
♙

Identity & access

Customers register and log in. A signed JWT is returned and sent with protected requests. The API verifies the token and checks the user’s current role in the database.

POST /register · /loginGET /users/me
02
▦

Catalog & collections

Products belong to categories. Anyone can browse; only an admin can create, edit, or delete catalog entries. Search and category filters run on the API.

GET /products?q=...POST /categories · /products
03
⌑

Cart & inventory

A cart belongs to the signed-in customer. It does not reserve stock. Checkout confirms availability, records the order, and deducts inventory in one transaction.

POST /cart/itemsPOST /orders/checkout
04
↗

Orders & fulfillment

Each order stores its price snapshot and line items. Customers see only their own orders; admins can advance status through the allowed fulfillment steps.

GET /orders · /orders/{id}PATCH /orders/{id}/status
05
⬡

Data & migrations

SQLAlchemy models map users, categories, products, carts, orders, and order items. Alembic migrations evolve the database schema safely.

models/alembic upgrade head
06
⌁

Health & documentation

The health route checks database connectivity. FastAPI generates an interactive OpenAPI reference so you can inspect and try every endpoint.

GET /healthGET /docs
